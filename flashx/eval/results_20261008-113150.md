# Evaluation run 20261008-113150

Flash-X MOL `44188e65b`, UniformMesh `fc83ecc`, RIKEN supercomp (GNU 14.3.1), 1 MPI rank.
All problems on 256 x 256 cells, CFL 0.5, blocks of at least 8 x 8 cells.
NewImpl runs on the UniformMesh inside Flash-X; the reference is plain Spark.

## Results

| Check | Result |
|---|---|
| Block splits (vortex, vortex fixed dt, Sod, Sod hybrid; down to 8 x 8 cells per block) | all bitwise identical to 1 x 1 |
| Vortex (dt from CFL): NewImpl vs Spark | difference = 1 % (L1) / 2.5 % (max) of the error vs exact |
| Vortex (fixed dt = 0.005): NewImpl vs Spark | difference = 0.001 % (L1) / 0.006 % (max) of the error vs exact |
| Vortex error vs exact (density, L1 / max) | CFL dt: 2.4e-5 / 8.0e-4; fixed dt: 1.8e-5 / 4.0e-4 (both codes the same) |
| Sod error vs exact (density, L1 / max) | NewImpl 3.4e-3 / 7.4e-2, Spark 3.8e-3 / 8.5e-2 (hybrid solver: same) |
| Sod mirror symmetry, max \|u(x)+u(x')\| | NewImpl 1.3e-2, Spark 1e-13 |

## Observations

- **The mesh integration is exact:** results do not depend on the block decomposition.
- **NewImpl matches Spark in smooth flow**, far below the discretisation error.
- **Exact roundoff agreement is not reached in long runs**, even with identical timesteps
  (max difference 2.7e-8). The difference sits in the nearly uniform background, where
  WENO-Z (epsilon 1e-36 in both codes) amplifies rounding differences: NewImpl evaluates the
  same formulas in a different order. With dt from the CFL condition, each code picks its
  own timesteps and the difference grows by about three orders of magnitude.
- **With dt from the CFL condition, NewImpl and Spark take different timesteps.** On Sod they
  therefore end at different times, so they are compared against the exact solution, not
  with each other.
- **NewImpl is slightly more accurate than Spark on Sod but breaks the mirror symmetry** at
  the waves, with and without the hybrid solver.
- **At CFL 0.5 both codes show a grid-scale checkerboard** in the vortex; the fixed-dt run
  (effective CFL about 0.375) does not, and its error is half as large. Possible cause: dt
  uses the largest directional signal speed, so the diagonal flow runs at roughly twice the
  nominal Courant number. A CFL 0.4 run is testing this.

## Criteria changed after this run

- Fixed-dt vortex: NewImpl vs Spark must be at most 1e-3 of the error vs exact (was 1e-12
  absolute). This run passes with the new criterion.
- New strict check: `vortex_short`, fixed dt, 100 steps, at most 1e-12.

## Follow-up run cfltest-20261008-1410

| Check | Result |
|---|---|
| `vortex_short` (fixed dt, 100 steps): block splits | bitwise identical |
| `vortex_short`: NewImpl vs Spark | max 1.2e-12 (just above the 1e-12 limit: FAIL), L1 1.7e-15 |
| `vortex_cfl04` (CFL 0.4): error vs exact (L1 / max) | 1.8e-5 / 4.0e-4 (CFL 0.5: 2.4e-5 / 8.0e-4) |
| `vortex_cfl04`: NewImpl vs Spark | identical timesteps (all 1877); difference 2e-5 of the error vs exact |

- **CFL 0.4 removes the checkerboard** and halves the maximum error; NewImpl and Spark then
  take identical timesteps even with dt from the CFL condition. The checkerboard at CFL 0.5 also caused the step
  drift between the two codes.
- **After 100 steps the codes already differ by up to 1.2e-12 in single cells** (L1 at
  rounding level). The strict limit of 1e-12 is too tight at 256 x 256; 1e-11 would fit.
